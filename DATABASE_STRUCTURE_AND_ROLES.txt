SECTION 0: ROLES & ACCESS CONTROL
====================================================================================================

A) APPLICATION ROLES  (stored in auth.users.raw_user_meta_data.role, mirrored to public.profiles.role)
----------------------------------------------------------------------------------------------------
  Role            | Display name | Scope
  ----------------+--------------+------------------------------------------------------------------
  super_admin     | Super Admin  | Everything: all hotels/boats, all bookings, analytics, users, blogs
  admin (legacy)  | Super Admin  | Treated exactly like super_admin (backwards compatibility)
  hotel_admin     | Hotel Admin  | Only hotels listed in user_metadata.hotel_ids[] (uuid array)
  (no role)       | Guest/User   | Regular customer: own bookings, own profile, own reviews

  user_metadata shape:
    { role?: 'super_admin' | 'hotel_admin' | 'admin', hotel_ids?: string[] }

  Permission matrix (lib/utils/roles.ts -> canPerformAction):
    Action              | super_admin | hotel_admin
    --------------------+-------------+------------
    view_all_hotels     |     YES     |    no
    edit_all_hotels     |     YES     |    no
    view_all_bookings   |     YES     |    no
    manage_users        |     YES     |    no
    view_analytics      |     YES     |    no
    access own hotels   |     YES     |    YES (hotel_ids only)

  Helper functions (lib/utils/roles.ts):
    isSuperAdmin, isHotelAdmin, isAnyAdmin, getAdminRole, getUserHotelIds (null = all hotels),
    hasHotelAccess, getRoleDisplayName, canPerformAction

  Server guards (lib/utils/admin.ts):
    isAdmin, checkIsSuperAdmin, checkIsHotelAdmin, getAdminUser, requireAdmin, requireSuperAdmin,
    requireHotelAdmin, getAdminHotelAccess -> { userId, role, hotelIds }, checkHotelAccess,
    requireHotelAccess(hotelId)

B) DATABASE ROLE-CHECK FUNCTIONS (SECURITY DEFINER, used in RLS policies)
----------------------------------------------------------------------------------------------------
  public.is_admin()        -> true if role IN ('super_admin','admin','hotel_admin')
  public.is_super_admin()  -> true if role IN ('super_admin','admin')
  public.is_hotel_admin()  -> true if role = 'hotel_admin'
  public.handle_new_user() -> trigger on auth.users: upserts public.profiles (id, email, role, hotel_ids)
  Some policies also check auth.jwt() ->> 'role' directly.

C) POSTGRES / SUPABASE ROLES (roles.sql)
----------------------------------------------------------------------------------------------------
  anon           -> unauthenticated API requests   (statement_timeout = 3s)
  authenticated  -> logged-in API requests         (statement_timeout = 8s)
  authenticator  -> PostgREST connection role      (statement_timeout = 8s)
  service_role   -> server-side key, bypasses RLS (GRANT ALL on tables)
  postgres       -> owner of all functions/tables

### VIEW: hotel_summary
    SELECT h.id,
        h.name,
        h.slug,
        h.city,
        h.star_rating,
        h.property_type,
        h.location_rating,
        count(DISTINCT r.id) AS review_count,
        round(avg(r.overall_rating), 1) AS avg_overall_rating,
        round(avg(r.staff_rating), 1) AS avg_staff_rating,
        round(avg(r.facilities_rating), 1) AS avg_facilities_rating,
        round(avg(r.cleanliness_rating), 1) AS avg_cleanliness_rating,
        round(avg(r.comfort_rating), 1) AS avg_comfort_rating,
        round(avg(r.value_rating), 1) AS avg_value_rating,
        round(avg(r.location_rating), 1) AS avg_location_rating_review,
        round(avg(r.free_wifi_rating), 1) AS avg_wifi_rating,
        min(rt.base_price) AS starting_price
       FROM ((hotels h
         LEFT JOIN reviews r ON (((h.id = r.hotel_id) AND ((r.status)::text = 'approved'::text))))
         LEFT JOIN room_types rt ON (((h.id = rt.hotel_id) AND ((rt.status)::text = 'available'::text))))
      WHERE ((h.status)::text = 'active'::text)
      GROUP BY h.id, h.name, h.slug, h.city, h.star_rating, h.property_type, h.location_rating

### VIEW: payment_reconciliation
    SELECT b.booking_reference,
        b.total_amount AS booking_amount,
        p.amount AS payment_amount,
        p.status AS payment_status,
        p.payment_gateway_payment_id,
        COALESCE(r.refund_amount, (0)::numeric) AS refund_amount,
        b.created_at AS booking_date,
        p.created_at AS payment_date,
        r.created_at AS refund_date
       FROM ((bookings b
         LEFT JOIN payments p ON ((p.booking_id = b.id)))
         LEFT JOIN refund_transactions r ON ((r.booking_id = b.id)))
      WHERE (p.id IS NOT NULL)
      ORDER BY b.created_at DESC

### VIEW: refund_summary
    SELECT date(created_at) AS refund_date,
        count(*) AS total_refunds,
        sum(refund_amount) AS total_refund_amount,
        sum(cancellation_charge) AS total_cancellation_charges,
        count(*) FILTER (WHERE is_full_refund) AS full_refunds,
        count(*) FILTER (WHERE (NOT is_full_refund)) AS partial_refunds,
        count(*) FILTER (WHERE ((status)::text = 'completed'::text)) AS completed_refunds,
        count(*) FILTER (WHERE ((status)::text = 'processing'::text)) AS pending_refunds,
        count(*) FILTER (WHERE ((status)::text = 'failed'::text)) AS failed_refunds
       FROM refund_transactions r
      GROUP BY (date(created_at))
      ORDER BY (date(created_at)) DESC
